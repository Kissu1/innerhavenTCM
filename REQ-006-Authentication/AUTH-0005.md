# AUTH-0005: Unauthenticated user is redirected to login

**Summary:** Verify that a user who is not logged in cannot access protected pages — any attempt to visit a protected route redirects them to the login page.

**Preconditions:**
- No user is logged in (no active session)
- The browser has no cached authenticated session

**Scenario 1: Protected route access blocked for unauthenticated users**

| Step | Expected Behavior |
|------|-------------------|
| 1. User attempts to navigate directly to the dashboard (`/dashboard`) | Verify that the browser is immediately redirected to the login page |
| 2. User attempts to navigate to the appointments page (`/appointments`) | Verify that the browser is redirected to the login page |
| 3. User attempts to navigate to the settings page (`/settings`) | Verify that the browser is redirected to the login page |
| 4. User attempts to navigate to the messaging page (`/messaging`) | Verify that the browser is redirected to the login page |
| 5. User navigates to a public page (e.g., the home page or login page) | Verify that the page loads normally — public pages are accessible without authentication |
| 6. User logs in successfully | Verify that they are now redirected to the dashboard and all previously blocked pages become accessible |

**Post-conditions:**
- All protected routes redirect unauthenticated users to the login page
- Public pages remain accessible without a session
- After login, the user can freely navigate all pages appropriate for their role
